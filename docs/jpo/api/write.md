# 객체 생성, 수정 <Badge type="info" text="원본 분석" />

OOTB JPO 가 객체를 만들고, 값과 상태를 바꾸고, 관계를 연결할 때 쓰는 메서드입니다. 넘기는 값은 모두 문자열이고 이름 (타입, 관계, 속성, 상태) 은 심볼릭 이름에서 얻은 실제 이름을 씁니다 ([심볼릭 이름](/jpo/domain-object#심볼릭-이름)).

::: info 근거
시그니처와 동작은 xerinfra.jar `DomainObject`, `DomainRelationship`, eMatrixServletRMI.jar `BusinessObject` class 파일 (javap) 기준. 건수는 jpo 폴더 바로 아래 1,615 개 파일에서 센 호출 수: `.setAttributeValue(context` 955, `DomainRelationship.connect(context` 549, `.setAttributeValues(context` 298, `.setState(context` 136, `.setDescription(context` 111, `.promote(context` 99, `.setOwner(context` 75, `.createObject(context` 64, `DomainRelationship.setAttributeValue(context` 54, `DomainRelationship.setToObject(context` 38, `.setName(context` 29, `.createAndConnect(context` 25, `.setPolicy(context` 20, `.cloneObject(context` 13, `.demote(context` 13, `.reviseObject(context` 12
:::

샘플: [XX_ObjectApi_mxJPO.java](https://github.com/LeeOuHyoun/3d-docs/blob/main/JPOSample/XX_ObjectApi_mxJPO.java) 의 `createDocument`, `updatePart`, `updateQuantity`, `releasePart`, `revisePart`

## 생성

| 메서드 | 하는 일 | 반환 |
| --- | --- | --- |
| `obj.createObject(context, type, name, revision, policy, vault)` | 객체를 만들고 `obj` 가 새 객체를 가리킴. id 는 `obj.getId(context)` | `void` |
| `obj.createAndConnect(context, type, rel, other, isFrom)` | 만들고 바로 `other` 와 연결 (한 트랜잭션). `isFrom` 이 `true` 면 `other` → 새 객체, `false` 면 새 객체 → `other` | `DomainRelationship` |
| `obj.cloneObject(context, newName)` | 복사본을 만듦 (파일 포함). 이름이 비면 자동 이름 | `BusinessObject` |
| `obj.reviseObject(context, withFiles)` | **마지막 리비전** 의 다음 리비전을 만듦. `withFiles` 가 `true` 면 파일도 복사 | `BusinessObject` |
| `DomainObject.getAutoGeneratedName(context, "type_X", "")` | 타입의 채번기로 이름만 만듦 | `String` |

`createObject` 에 `null` 이나 `""` 를 넘기면 아래 기본값을 씁니다.

| 인자 | 비었을 때 |
| --- | --- |
| `name` | 고유 이름 (`getUniqueName`) |
| `revision` | 정책의 첫 리비전 |
| `policy` | 타입의 기본 정책 |
| `vault` | 기본 vault |

```java
DomainObject doc = DomainObject.newInstance(context);
doc.createObject(context, typeDocument, null, null, null, null);
String newId = doc.getId(context);

DomainObject doc2 = DomainObject.newInstance(context);
DomainRelationship rel = doc2.createAndConnect(context, typeDocument, relPartDocument, part, true);

String nextId = part.reviseObject(context, false).getObjectId(context);
```

- `createObject`, `createAndConnect`, `cloneObject`, `reviseObject` 는 안에서 트랜잭션을 열고 닫습니다. 바깥에 트랜잭션이 있으면 그 안에 묶입니다 ([트랜잭션](/jpo/transaction-context#트랜잭션)).
- 채번기로 이름을 붙여 만들려면 `FrameworkUtil.autoName` 을 씁니다 ([채번기](/trigger/generator)).

::: info 근거
xerinfra.jar `DomainObject.createAndConnect(context, type, rel, other, isFrom)` → `(context, type, name=null, rel, other, isFrom)` → `(context, type, name, revision=null, policy=null, vault=null, rel, other, isFrom)`: `startTransaction`, vault 가 비면 `getDefaultVault(context, other)`, `createObject`, `connect(context, rel, other, isFrom)`, `commitTransaction`. `reviseObject(context, withFiles)` 는 `getLastRevision` → `getNextSequence` → `BusinessObject.revise(context, visuals, 다음리비전, vault, withFiles)`. `cloneObject(context, name)` 는 `cloneObject(context, name, null, null, true)` (파일 복사), 이름이 비면 `getDefaultName`, 타입의 admin property `AutoGeneratedObjectName` 이 `true` 면 `getAutoGeneratedName`. 호출 예: emxCommonEngineeringChangeBase_mxJPO.java:8050 (`reviseObject(context, inheritFiles)`), emxControlledFolderBase_mxJPO.java:555
:::

## 값 수정

| 메서드 | 하는 일 | 반환 |
| --- | --- | --- |
| `obj.setAttributeValue(context, 속성, 값)` | 속성 하나 | `void` |
| `obj.setAttributeValues(context, map)` | 속성 여러 개 한 번에 (속성 이름 → 값) | `void` |
| `obj.setDescription(context, 설명)` | 설명 | `void` |
| `obj.setOwner(context, 사용자)` | 소유자. `changeOwner` 도 같은 일 | `void` |
| `obj.setName(context, 이름)` | 이름 바꾸기 (TNR 변경). 같은 이름이면 아무것도 안 함, 비면 예외 | `void` |
| `obj.setPolicy(context, 정책)` | 정책 바꾸기. `changePolicy` 도 같은 일 | `void` |
| `obj.setVault(context, vault)` | vault 바꾸기 | `void` |
| `MqlUtil.mqlCommand(context, "modify bus $1 $2 $3", id, 속성, 값)` | MQL 로 직접 ([MqlUtil](/jpo/mql-util)) | `String` |

```java
Map attrs = new HashMap();
attrs.put(attrStatus, "Approved");
attrs.put(attrComment, comment);
part.setAttributeValues(context, attrs);
part.setDescription(context, "설명");
part.setOwner(context, newOwner);
```

- 날짜 속성은 `MM/dd/yyyy hh:mm:ss a` 형식 문자열로 씁니다 ([날짜](/jpo/utils#날짜)).
- 사용자에게 수정 권한이 없으면 예외가 납니다. 시스템이 대신 바꿔야 하면 [pushContext](/jpo/transaction-context#슈퍼유저로-바꾸기-pushcontext) 로 감쌉니다.

## 상태 바꾸기

| 메서드 | 하는 일 | 반환 |
| --- | --- | --- |
| `obj.promote(context)` | 다음 상태로 한 단계 | `void` |
| `obj.demote(context)` | 이전 상태로 한 단계 | `void` |
| `obj.setState(context, 상태)` | 목표 상태까지 promote / demote 를 되풀이. 정책에 없는 상태면 예외 | `int` |
| `obj.setState(context, 상태, false)` | 위와 같고 promote 할 때마다 먼저 `LifeCycleUtil.checksToPromoteObject` 를 부름 | `int` |

- `setState` 가 돌려주는 값은 움직인 단계 수입니다. 앞으로 가면 양수, 뒤로 가면 음수, 이미 그 상태면 `0` 입니다.
- 상태 이름은 실제 이름입니다. `PropertyUtil.getSchemaProperty(context, "policy", 정책, "state_Release")` 로 얻습니다.
- promote, demote 에는 정책의 상태 트리거가 걸립니다 ([라이프사이클과 promote](/trigger/lifecycle)).

```java
String policy = part.getInfo(context, DomainConstants.SELECT_POLICY);
String release = PropertyUtil.getSchemaProperty(context, "policy", policy, "state_Release");
int moved = part.setState(context, release);
```

::: info 근거
xerinfra.jar `DomainObject.setState(context, state)` → `setState(context, state, true)`. 정책 상태 목록에서 현재 위치와 목표 위치를 찾고, 없으면 `emxFramework.Beans.DomainObject.StateNotFound` 문구로 `FrameworkException`. 목표가 뒤에 있으면 `promote` 를 되풀이 (세 번째 인자가 `false` 면 그 전에 `LifeCycleUtil.checksToPromoteObject`), 앞에 있으면 `demote`. 한 단계마다 `current` 가 바뀌지 않으면 `PromotionFailed` / `DemotionFailed` 예외. 반환은 목표 위치 - 현재 위치
:::

## 연결

| 메서드 | 하는 일 | 반환 |
| --- | --- | --- |
| `DomainRelationship.connect(context, from, rel, to)` | `from` → `to` 연결 | `DomainRelationship` |
| `DomainRelationship.connect(context, fromId, rel, toId, preserve)` | id 로 연결. MQL `connect businessobject $1 relationship $2 to $3` (`preserve` 가 `true` 면 `preserve` 를 붙임) | `void` |
| `DomainRelationship.connect(context, obj, rel, isFrom, ids)` | 객체 하나에 여러 객체를 한 트랜잭션으로. `isFrom` 이 `true` 면 `obj` → `ids`, `false` 면 `ids` → `obj` | `Map` (상대 id → 관계 id) |
| `obj.connectTo(context, rel, other)` | `obj` → `other` | `DomainRelationship` |
| `obj.connectFrom(context, rel, other)` | `other` → `obj` | `DomainRelationship` |
| `obj.connect(context, rel, other, isFrom)` | `isFrom` 이 `true` 면 `other` → `obj`, `false` 면 `obj` → `other` | `DomainRelationship` |
| `obj.addToObject(context, new RelationshipType(rel), toId)` / `addFromObject(...)` | id 로 `obj` → `toId` / `toId` → `obj` | `DomainRelationship` |

::: warning 같은 true 라도 방향이 다릅니다
`DomainRelationship.connect(context, obj, rel, true, ids)` 는 `obj` 가 from 쪽입니다. `obj.connect(context, rel, other, true)` 와 `createAndConnect(..., other, true)` 는 `other` 가 from 쪽입니다. 헷갈리면 방향이 이름에 드러나는 `DomainRelationship.connect(context, from, rel, to)` 를 씁니다.
:::

```java
DomainRelationship rel = DomainRelationship.connect(context, part, relPartDocument, doc);
rel.setAttributeValue(context, attrQty, "2");
String relId = rel.getName();
Map relIds = DomainRelationship.connect(context, part, relPartDocument, true, docIds);
```

- 관계 id 는 `rel.getName()` 으로 얻습니다 (OOTB 도 이 값을 관계 id 로 씀).
- 관계 / 타입 이름은 화면 표시 이름이 아니라 스키마 이름입니다.

::: info 근거
xerinfra.jar: `DomainRelationship.connect(context, from, rel, to)` 는 `from.connect(context, relType, true, to)` (`BusinessObject.connect` 의 세 번째 인자 `true` = 호출한 객체가 from). `DomainRelationship.connect(context, obj, relType, isFrom, ids, ...)` 는 id 마다 `obj.connect(context, relType, isFrom, 상대)` 를 부르고 `상대 id → Relationship.getName()` 을 Map 에 담음. `DomainObject.connect(context, rel, other, isFrom)` 는 `isFrom` 이면 `addFromObjects` (= `DomainRelationship.connect(context, other, rel, this)`), 아니면 `addToObjects` (= `connect(context, this, rel, other)`). `connectTo` → `addToObjects`, `connectFrom` → `addFromObjects`. 결과 Map 사용 예: emxProjectBudgetBase_mxJPO.java:1833-1834
:::

## 관계 수정

| 메서드 | 하는 일 | 반환 |
| --- | --- | --- |
| `DomainRelationship.setAttributeValue(context, relId, 속성, 값)` | 관계 속성 하나 | `void` |
| `DomainRelationship.setAttributeValues(context, relId, map)` | 관계 속성 여러 개 | `void` |
| `rel.setAttributeValue(context, 속성, 값)` | 인스턴스 형태 | `void` |
| `DomainRelationship.setToObject(context, relId, newTo)` | to 쪽 객체 바꾸기. `modifyTo` 도 같은 일 | `void` |
| `DomainRelationship.setFromObject(context, relId, newFrom)` | from 쪽 객체 바꾸기. `modifyFrom` 도 같은 일 | `void` |
| `DomainRelationship.setType(context, relId, 관계)` | 관계 종류 바꾸기 | `void` |

```java
DomainRelationship.setAttributeValue(context, relId, attrQty, "3");
DomainRelationship.setToObject(context, relId, DomainObject.newInstance(context, newPartId));
```

::: info 근거
xerinfra.jar `DomainRelationship`: `setToObject` / `setFromObject` 는 MQL `modify connection $1 to $2` / `modify connection $1 from $2`, `modifyTo` / `modifyFrom` 은 이 두 메서드를 그대로 부름. `setType` 은 `modify connection $1 type $2`. static `setAttributeValue(context, relId, attr, value)` 는 `new DomainRelationship(relId).setAttributeValue(context, attr, value)`
:::
